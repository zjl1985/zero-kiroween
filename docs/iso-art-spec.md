# 等距 HD-2D 像素美术规格

状态：用户 2026-11-23 决定（“按照推荐”）后的执行规格，配合 [`docs/ISOMETRIC_PIXEL_PLAN.md`](ISOMETRIC_PIXEL_PLAN.md)。这里的数字是后续代码与测试的依据；改数字要同步改本文件和对应测试。通过测试不等于美术获认可。

参考作品（最终幻想战略版的等距地图与 4 向精灵，八方旅人的 HD-2D 光影）只在文字里描述，不导入仓库，不当素材、不当背景。

## 1. 投影

- 模拟坐标不变：俯视世界坐标 (x, y)，单位是世界单位。地形完全平坦，没有 z。
- 正投影（k = 1）：
  - `sx = x − y`
  - `sy = (x + y) / 2`
- 反投影：
  - `x = sx / 2 + sy`
  - `y = sy − sx / 2`
- 雅可比行列式为 1：一屏看到的世界面积与俯视版相同。
- 方向：世界 +x 指向屏幕右下，世界 +y 指向屏幕左下，世界 (−1, −1) 是屏幕正上方。
- 深度键：`depthKey = x + y`（脚点），越大越靠前、越晚画；相等时按实体 id（数字或字符串比较）稳定排序，再相等按注册顺序。多格建筑用覆盖区最靠前的角计算深度键，必要时拆成前后两半入队。
- 整像素取整规则：
  - 先在浮点里完成投影与减去镜头偏移，最后只取整一次：`snap(v) = Math.floor(v + 0.5)`，对负数同样成立，不用 `Math.round`（负半数方向不一致）。
  - 镜头偏移本身先取整，所以同一缓存地块在相邻帧里不会抖半像素。
  - 精灵按脚点锚点对齐整像素；不对像素图做旋转、缩放或仿射变换。地面上的形状（圆、矩形、多边形）先投影顶点再画。
- 世界里的圆在屏幕上是 2:1 椭圆（横半轴 = r·√2，纵半轴 = r·√2/2）；矩形是平行四边形。

## 2. 地块与网格

- 一个地块 = 32 × 32 世界单位 = 屏幕上 64 × 32 像素菱形，与褪色网格（32 单位）对齐。
- 火焰格是 24 单位方格，画成 48 × 24 像素菱形。
- 地块纹理以屏幕坐标为相位，64 × 32 菱形上下左右平铺无缝；每种地表 3～5 个变体，按 `hash2`（渲染哈希）选择，不用模拟 RNG。

## 3. 像素密度与角色高度

- 内部画布 960 × 540 原生像素，1 逻辑像素 = 1 画布像素，CSS 最近邻放大。
- 猫：44～52 像素高（脚底到耳尖）。
- 普通敌人：28～48 像素高。Boss（Eraser）约 96 像素。
- 居民：36～48 像素。拾取物：8～14 像素。

## 4. 朝向与动画

- 4 向：东南（SE，正面偏右）、东北（NE，背面偏右）手绘；西南（SW）= SE 水平镜像，西北（NW）= NE 水平镜像。
- 镜像时不对称的识别点（例如 Zero 的金链挂向、服装上的单侧配饰）要在镜像后的帧里重新贴到正确一侧，不能直接翻转。
- 朝向由渲染时的速度推出：屏幕方向的 x 分量决定左右，y 分量决定正面或背面；静止时保持上一个朝向。模拟只有左右 `facing`，不改。
- 帧数：待机 2 帧，走路 4～6 帧（猫 6，普通敌人 4），受伤 1 帧。减弱动态只用第 0 帧。
- 镜头固定一个角度，不做旋转。

## 5. 光照方向与明暗

- 月光从屏幕右上方来，硬投影朝屏幕左下方。烘焙进精灵和体块。
- 体块三面明度：顶面最亮；朝光的右侧面（屏幕右边，朝东南）次之；背光的左侧面（屏幕左边，朝西南）最暗。顶、亮侧、暗侧分别用色阶的第 4、3、2 阶（从 0 数，0 最暗），高光点用最高阶，接地缝用第 0 阶。
- 冷暖：亮部偏暖（偏黄橙），暗部偏冷紫；不要只调明度。
- 暖色点光源（窗、灯笼、南瓜、蜡烛、火焰）由光照缓冲叠加，不改素材本身的色阶。

## 6. 轮廓

- 外轮廓 1 像素 sel-out：用相邻内部像素同色相的更深一阶（不是统一黑线），受光一侧可省略或用中间阶。
- 不留半透明杂边：精灵 alpha 只有 0 或 1（光斑、雾、粒子除外）。

## 8. HD-2D 图层顺序

每帧从下到上：

1. 场景：烘焙的地面块 → 按 `depthKey` 排序的体块、植被、道具、角色、敌人、弹道。
2. 光照缓冲：环境夜色（冷蓝紫，随夜晚进度变化，天亮转暖，读 `dawnAmount`）＋ 缓存光斑精灵，乘回场景（multiply）。没有光源时不做额外合成。
3. 雾：低处地雾两层视差。
4. 粒子：萤火虫、落叶、灰烬、水面闪烁；用渲染侧哈希，不用模拟 RNG；减弱动态时停止装饰动画。
5. 预模糊的远景层（地图外树墙、夜雾）与前景层（屏幕边缘树叶）：预先模糊后缓存，不在每帧设置 `ctx.filter`。游戏区域本身保持清晰。
6. 屏幕空间界面：导航箭头、伤害数字、提示文字、HUD。

## 9. 不变

- 模拟（`src/game/`、`src/defs/`）的数值、碰撞、水域多边形、火与褪色网格、刷怪、掉落都不改；渲染不改状态、不用模拟 RNG。
- 体块覆盖区必须与模拟碰撞一致（有测试）。
- 单猫规则、服装只是叠层、文字走 `t()`、中英两包同步。
