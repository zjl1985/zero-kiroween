## 1. 目标拆解：两个参考到底是什么

| | 最终幻想战略版（FFT） | 八方旅人（Octopath Traveler，HD-2D） |
| --- | --- | --- |
| 投影 | 真等距：2:1 菱形地块，世界旋转 45°，正交相机 | 透视 3D 相机，略俯视（约 30°～40°），**世界不旋转**，横平竖直 |
| 地形 | 有高度层的方块地图，侧面可见，地图像悬空的积木台 | 3D 网格地形 + 像素贴图 |
| 角色 | 像素精灵，4 个斜向（画 2 个正面斜向 + 2 个背面斜向，左右镜像） | 像素精灵永远正对镜头，左右镜像 |
| 氛围 | 平光、手绘色板 | 景深模糊、泛光、动态点光源、体积光、雾、粒子 |

用户写的是“斜 45 度”，与 FFT 的等距视角一致；“精细”“八方旅人”指的是 HD-2D 的光影与氛围。本计划推荐 **混合方案**：FFT 的 2:1 等距地图与 4 向精灵，叠加 HD-2D 的夜间光照、雾、景深与粒子。下一节第一个决定请用户确认。

## 2. 开工前需要用户拍板的决定

每条给出推荐项。用户回复编号即可，例如“D1=C，D2=H0，其余按推荐”。

**D1 投影方式**
- A 纯 FFT 等距：2:1 菱形，世界旋转 45°，平光。
- B 纯 HD-2D：世界不旋转，只把俯视改成斜俯视透视，加景深和光照。改动最小，但不是“斜 45 度”。
- **C（推荐）混合**：A 的地图与角色朝向 + HD-2D 的光照、雾、景深、粒子。

**D2 高度层**
- **H0（推荐先做）仅视觉高度**：模拟仍是平面。台地、悬崖、台阶只出现在不可走区域、地图边缘和地标底座，或作为不影响碰撞的装饰坡。
- H1 玩法高度：模拟加高度图（坡道、高处遮挡、投射物越过高差）。改动确定性模拟与平衡，放到垂直切片通过之后再议。

**D3 素材来源**
- **M1（推荐）代码建模 + 像素烘焙**：建筑、地块用代码体块（盒子、山墙屋顶、圆柱）描述，按等距角度栅格化成像素，再加手工细节层；树、植被、角色用代码逐像素绘制。可复现、可测试，角度一致。
- M2 再次图像生成等距素材：需要用户授权（付费服务、不可逐像素复现），而且生成图很难保证同一物件多个角度、同一像素密度一致。
- M3 混合：M1 为主，个别复杂地标用 M2 做参考稿，再按 M1 重画。
- 现有 `assets/village/generated/` 素材是俯视/斜俯视画的，**不能直接用于等距**。保留在仓库作历史与配色参考，运行时逐步停用。

**D4 角色朝向**
- **4 向（推荐）**：东南、西南、东北、西北；画东南与东北两张，另两张水平镜像（FFT 做法）。
- 8 向：多一倍工作量，收益小。

**D5 像素密度与投影比例**
- **推荐**：内部画布保持 960 × 540 原生像素，1 像素 = 1 屏幕像素，CSS 最近邻放大。投影系数 k = 1：屏幕 x = x − y，屏幕 y = (x + y) / 2。雅可比行列式为 1，一屏看到的世界面积与现在相同，敌人密度、视野不变。32 世界单位的地块 = 64 × 32 像素菱形，与褪色网格（32 单位）对齐。
- 猫约 44～52 像素高，普通敌人 28～48 像素，Boss 约 96 像素；高度层每级 16 像素。
- 备选：k = 0.75（看得更远、物件更小），会改变视野与可读性，需试玩。

**D6 HD-2D 后期的实现层**
- **P1（推荐先做）纯 Canvas 2D**：离屏光照缓冲（缓存的光斑精灵叠加后乘回场景）、分层雾、预模糊的远景/前景层做假景深、粒子。

**D7 镜头旋转**：**推荐固定一个角度**（FFT 可转 4 个角度，但会让所有素材工作量翻 4 倍）。

## 4. 技术架构

### 4.1 核心思路：模拟不动，渲染换投影

模拟继续用俯视世界坐标 (x, y)。新建 `src/render/iso/` 目录，所有等距逻辑集中在这里：

```
src/render/iso/
  projection.ts     ISO 常量；toScreen(x, y, z)、toWorld(sx, sy)、depthKey(x, y, z)、像素取整规则
  iso-camera.ts     屏幕空间跟随镜头、按投影后的世界菱形夹紧、视口反投影为世界多边形
  cull.ts           反投影视口的世界 AABB + 多边形精确剔除
  palette.ts        各材质的色相偏移色阶（草、土、石、木、瓦、水、布）与夜间分级
  terrain-field.ts  纯函数：世界点 -> 材质（道路、水浅/深、桥面、菜地、分区地表）+ 到边界的距离
  terrain-bake.ts   逐像素反投影取材质，按等距纹理相位上色，烘焙屏幕空间地块缓存
  model.ts          体块建模 DSL：box、gable（山墙屋顶）、hip、cylinder、prism，面材质
  rasterize.ts      体块 -> 等距像素：可见面判定、顶/左/右三面明度、轮廓 sel-out、细节层回调
  sprite-sheet.ts   4 向 × 动作帧的代码像素角色表，镜像规则，缓存键
  depth.ts          脚点深度排序、多格建筑的覆盖区排序、遮挡淡化/切开
  lighting.ts       光照缓冲：环境夜色 + 缓存光斑 + 窗光 + 火光，月光方向
  post.ts           雾层、假景深（远/近层预模糊）、粒子
  debug-grid.ts     ?iso=grid 开发视图：菱形网格、碰撞圆投影成椭圆、水域多边形描边
```

### 4.2 投影公式（D5 推荐值）

- 屏幕 x = (x − y) · k，屏幕 y = (x + y) · k / 2 − z · zScale；k = 1，zScale = 1（每 16 单位高度 = 16 像素）。
- 反投影：x = sx / (2k) + sy / k，y = sy / k − sx / (2k)（z = 0）。
- 深度键：x + y 为主键，z 为次键，实体 id 为最后的稳定键。
- 世界里的圆（碰撞半径、武器范围、预警圈）在屏幕上是 2:1 椭圆；矩形（Eraser 横扫 300 × 70）是平行四边形。所有地面形状一律“投影顶点后再画”，**不对像素图做仿射变换**（否则像素会被旋转、出现锯齿和模糊）。

### 4.3 地面：逐像素场采样，而不是旋转贴图

- 现有地面是世界坐标矩形块，旋转后无法保持像素清晰。新地面按 **屏幕空间块**（例如 512 × 256 像素）缓存：块内每个像素反投影到世界点，查询 `terrain-field.ts` 得到材质与边界距离，再用以屏幕坐标为相位的等距纹理上色。
- 这样水岸、道路边与模拟多边形逐像素一致（测试可直接验证），同时纹理像素始终对齐屏幕网格。
- 每块约 13 万次场查询，只在烘焙时发生，可放进现有 `terrain-worker.ts`；缓存上限沿用现有 14 块的内存量级（按面积折算），LRU 淘汰。

### 4.4 立体物件：体块建模 + 烘焙

- 建筑和地标用 `model.ts` 拼体块，`rasterize.ts` 按固定等距角度输出像素：顶面最亮、朝月光的侧面次之、背光侧面最暗，每种材质 4～6 阶色相偏移色阶；外轮廓 1 像素同色相加深（沿用 sel-out 规则）。
- 窗、门、瓦、木筋、苔藓等细节在每个面的局部 2D 坐标里手绘，再随面一起投影（面内细节用剪切映射到菱形面，按整像素步进，保持清晰）。
- 体块的底面覆盖区必须与模拟碰撞（`SOLID_SCENERY` 胶囊、地标半径、道具碰撞圆）一致，有测试。
- 现有 `pixel-stack.ts` 可在 turn = π/4、squash = 0.5 下渲染等距体积，可作为树干、石块、桶等圆形物件的快速通道，但需要逐件检查像素质量。

### 4.5 排序与遮挡

- 普通物件、角色、敌人、拾取物按脚点 `depthKey` 排序。
- 多格建筑按覆盖区“最靠前的角”排序，必要时把建筑切成前后两半分别入队，避免猫站在屋侧时被错误盖住。
- 猫在建筑后面时：屋顶和前墙半透明或切开（FFT 的做法），猫的轮廓始终可见。替换现有 `paperOccludesActor`。

### 4.6 光照与氛围（HD-2D 部分）

- 环境：夜色分级（冷蓝紫）随夜晚进度变化，天亮时转暖，复用 `dawnAmount`。
- 光源：路灯、窗、灯笼、南瓜、蜡烛、火焰格、技能命中，统一是缓存的光斑精灵，叠加进光照缓冲后与场景相乘；数量上限与距离剔除。
- 月光：固定方向的硬投影（屏幕右上来光，影子向左下），物件阴影在烘焙时画进精灵。
- 雾与粒子：低处地雾两层视差、萤火虫、落叶、灰烬、水面闪烁；减弱动态时停止装饰动画。
- 假景深：远景（地图外的崖壁/远山）与最前景（屏幕边缘的树叶）使用预模糊缓存层；游戏区域本身保持清晰，避免影响敌人可读性。

### 4.7 输入

- `main.ts` 在 `input.sample()` 之后、`step()` 之前把屏幕方向转换为世界方向（纯函数 `screenToWorldDir`，放在 `src/render/iso/projection.ts` 或 `src/ui/`，有测试）。触摸摇杆同理。
- 模拟、固定输入回放、平衡脚本都直接输入世界向量，结果不变。

## 7. 风险与对策

- **代码画像素的质量上限**：体块烘焙容易显得“程序化”。对策：每个建筑都有手绘细节层；M1 先用一栋房子定质量标准，用户认可后再批量。
- **地面采样与模拟形状不一致**：对策：地面直接用模拟同一套纯函数采样，测试逐像素比对。
- **排序错误**（猫被房子错盖）：对策：覆盖区排序 + 前后切半，`?iso=grid` 调试视图，专门的遮挡测试。
- **性能**：屏幕块烘焙比现在重。对策：worker 烘焙、LRU、光源上限、粒子上限；用户实测帧时，不凭 Node 结果宣称流畅。
- **现有生成素材作废**：俯视素材不能转等距。保留文件，不删除；是否重新生成等距素材是 D3 的决定。
- **工作量与截止**：见 D10，先切片后铺开。
