# Add or change user-facing strings

Every string a player sees goes through `t(locale, key, values?)` from `src/content/i18n.ts`. No literal player-facing text in render or UI code. Static markup in `index.html` is filled by the `paint()` labels map (`src/main.ts`, element id -> key); a new labelled element needs an entry there.

Files:

- `src/content/keys.ts`: `MESSAGE_KEYS` (an `as const` array), `MessageKey`, `Locale = "zh" | "en"`, `Messages = Record<MessageKey, string>`.
- `src/content/en.ts` (`EN: Messages`) and `src/content/zh.ts` (`ZH: Messages`). Because both are typed `Messages`, `tsc` fails if a pack misses a key.
- `src/content/i18n.ts`: `t()` replaces `{name}` placeholders from `values` and returns `[missing: key]` for an empty entry; `missingKeys(locale)` lists keys with no text (tests assert it is empty for both packs); `formatTime(seconds)`.

`zh` is the default locale (`initialPrefs()` in `src/main.ts`, `<html lang="zh-Hans">` in `index.html`). Switching the default to English is planned for later; ask the user before removing the Chinese pack or the language toggle.

## Steps

1. Append the key to `MESSAGE_KEYS` in `src/content/keys.ts`, next to related keys.
2. Add the English text to `src/content/en.ts` and the Chinese text to `src/content/zh.ts`. Keep placeholders identical in both (`{damage}`, `{name}`).
3. Use it: `t(locale, "gallery.title")`. Keys built from ids need a cast: ``t(locale, `upgrade.${id}.name` as MessageKey)``.
4. `npm run build` (type check catches missing pack entries) and `npm test`.

## Key families that content defs need

| Content | Keys |
| --- | --- |
| Cat `<id>` (`CharacterDef.i18n` prefix) | `<id>.name`, `.role`, `.story`, `.tactic`, `.attack.name`, `.attack.desc`, `.active.name`, `.active.short`, `.active.desc`, `.passive.name`, `.passive.desc`; `cat.<id>.choice`; `notice.<skillNotice>` |
| Weapon, evolved weapon, passive | `upgrade.<id>.name`, `upgrade.<id>.desc` (params from `base` / `values`, through `upgradeParams` in `src/game/upgrades.ts`) |
| Evolution | `notice.<EvolutionDef.notice>` |
| Enemy | `enemy.<id>.name` |
| Prop | `prop.<id>.name` |
| Landmark | `landmark.<id>`, `notice.found-<id>` |
| Biome | `biome.<id>.name` |
| Sim notice | `notice.<Notice>` (the `Notice` union in `src/game/types.ts`; `hud.ts` shows `notice.${kind}`) |
| Gallery | `gallery.section.<name>`, `gallery.state.<state>` |

Cat copy params come from `CharacterDef.copyParams()`; the UI merges every cat's params, so text may cite numbers by name (`{decoy}`, `{stars}`).

## Tests

`tests/registry.test.mjs` "every def has its name (and card description) in every language pack" and the landmark / biome test check the families above for every registered def. `tests/reactions.test.mjs` checks prop names, `tests/gallery.test.mjs` checks gallery labels, `tests/upgrades.test.mjs` and `tests/journal.test.mjs` check their own strings in both packs.
