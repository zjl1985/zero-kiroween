# Design: Midnight Meow

## Overview

A static site (`index.html`, `styles.css`, compiled modules in `dist/`, isolated published output in `site/`) with no framework or runtime dependencies. Content is built as **definitions + hooks + registries**: a content-agnostic engine, content definitions, a generic DOM-free simulation, a registered art layer on Canvas and a thin DOM UI, wired together in `src/main.ts`. A run is a 10-minute survivor-like night in a bounded seeded town with a follow camera. The workflow for adding content is the `midnight-meow-dev` skill (`.kiro/skills/midnight-meow-dev/`).

## Architecture

```
src/engine/   registry.ts  events.ts  sprite.ts          (content-agnostic, imports nothing of ours)
                 │            │          │
src/defs/     registries.ts (CATS, WEAPON_DEFS, PASSIVE_DEFS, EVOLUTION_DEFS, ENEMY_DEFS, BEHAVIOURS,
              MATERIALS, REACTIONS, PROP_DEFS, LANDMARK_DEFS, BIOME_DEFS, SIM_EVENTS)
              index.ts ── registers sim defs, gates hooks      world-index.ts ── world defs
              cats/ weapons/ passives/ evolutions/ enemies/ reactions/ props/ landmarks/ biomes/
                 │  (def files: numbers + hooks)                    │  (art files beside them)
                 ▼                                                  ▼
input.ts / touch.ts ─► FrameInput ─► sim.step(state, input, FIXED_DT) ─► SimState
                                      │ SimContext helpers, SIM_EVENTS   │
                                      │ world-gen.ts (pure seed hash)    │
                                      ▼                                  ▼
            render/art-index.ts ─► art registries ─► world.ts (craft-world, craft-props, craft-scene,
                                                     craft-cat, craft-enemies, craft-juice, combat-fx, cue-fx)
                                                       │
                                          2x back canvas ─► stage canvas
hud.ts / journal.ts / character-panel.ts / upgrade-cards.ts ◄── SimState + registries + i18n
gallery-layout.ts + render/gallery.ts ◄── registries (?gallery=1, no sim)
main.ts cueState (diff of sim counters) ─► audio/sfx.ts and timeline.ts cues
```

### Engine (`src/engine/`)

- `createRegistry<T>(kind)`: `register` (throws on a duplicate id), `get` (throws with the registered ids on an unknown id), `find`, `has`, `all`, `ids`. Registration order is kept and is part of the contract.
- `createEventBus<S, E, C>()`: synchronous typed events; handlers run in registration order inside `emit`; handler lists live in module scope, never in `SimState`.
- `cachedSprite(key, w, h, scale, paint, anchor)`: offscreen canvas cache with LRU eviction at `SPRITE_CACHE_LIMIT` 256; without a DOM it calls the painter directly. `imageSprite` exists as a capability; nothing shipped uses images.
- A test enforces that `src/engine/` imports nothing from game, defs, render, ui or content.

### Definitions (`src/defs/`)

- `types.ts` holds every interface: `CharacterDef`, `WeaponDef` (`timing` "move" / "aura" / "auto", `steps`, `base`, `elements`, `shotTag`, `stats`, `step`, `init`, `hooks`), `PassiveDef` (`modify`, `onLevel`), `EvolutionDef`, `EnemyDef` (`behaviours`, `onSpawn`, `onDeath`, `catSlow`, `stepWorld`, `arrival`), `EnemyBehaviour` (`speed`, `steer`), `SimContext`, `SimEvents` (tick, hit, kill, dash, damaged, pickup, levelUp, chestOpen, touchProp), `MaterialDef`, `ReactionDef`, `PropDef` (optional flora `regrow`), `LandmarkDef` (optional `water` / `activity`), `LandmarkActivity`, `BiomeDef` (optional `water`), `WaterShape`, `WaterRegion`, `WaterCrossing`. Def files add their own `PlayerStats` fields by module augmentation.
- `index.ts` registers cats (zero, nicole), weapons (meow-bolt, night-claw, echo-legion, moon-stars, star-fall, full-moon, paper-crane, pumpkin-seed, watercolour-brush, paper-cut, page-fold), passives (vitality, swift, magnet, focus, scholar, paper-armor, night-eyes, long-shadow, deep-fold, moon-shield, snack), evolutions (echo-legion, full-moon), behaviours (chase, swoop, kite-lob, boss-hunt, ghost-glide) and enemies (ink-blob, paper-bat, crumple, smudge, eraser-boss, kiro-ghost, wash, sketch). Cat hooks run only for the chosen cat; weapon and passive hooks only while owned (or the start weapon).
- `world-index.ts` registers 6 materials, 27 unique material x element rows (including four `wash-*` rows for `water`), 18 props (the last is water-bucket), 12 landmark kinds and 5 biomes; `src/game/world-gen.ts` imports it directly to avoid an import cycle through `horde.ts`. Ink-vat and wax-candle are real props; card/cloth fire rows and ink/fold sources/treatments are implemented, not deferred.
- Data modules: `progression.ts` (`BUILD`, `XP`), `horde.ts` (`HORDE`, `FILLER_KIND`, `KIND_CAP`, `PHASE_AT`, `ELITE`, `SPAWN_TABLE`, `WAVES`, `WAVE_RING`), `fire.ts` (`FIRE`, `PROP_HITS`), `water.ts` (`WATER` and pure polygon helpers), `ecology.ts` (safe restoration/ink fuel tuning), `reactions/paper-status.ts` (`PAPER_ELEMENTS`), `landmark-activities.ts` (court anchors, rewards and activity definitions), `materials.ts`, `biomes/districts.ts` (`DISTRICTS`, `BASE_DECOR`), and the Boss numbers in `enemies/eraser-boss/def.ts`.
- RNG: `SimContext` has no RNG. The sim passes its step `Rng` only to `WeaponDef.step` and `EnemyBehaviour.steer`, so RNG use stays visible at the call sites.

### World (`src/game/world-gen.ts`)

- `WORLD` is 10 x 10 screens of 960 x 540 (9600 x 5400; x -4320..5280, y 0..5400). The start yard keeps its original 0..960 x 0..540 coordinates at the middle of the north edge. The north edge is the hill horizon (actors stay below `WORLD.playTop` 264); the west, east and south edges are a paper hedge (`WORLD.edge` 36). The size is a tunable constant.
- `CHUNK` tiles the world in 480 x 540 chunks (20 x 10). `chunkContent(seed, cx, cy)` is a memoised pure hash of the seed and chunk coords that returns decor, props, colliders, interactable spots and the chunk's biome, so the sim and renderer agree without the sim RNG.
- Landmarks: one per super-cell (`LANDMARK` 5 x 5, start cell skipped, 24 in total), every registered kind at least once: clock tower, pumpkin patch, stone bridge, chapel yard (`graveyard`), lantern market, moon hill, paper windmill, puppet theatre, wishing well, paper teahouse, fold greenhouse, star observatory. `landmarkParts(l)` runs the def's `layout` with a `LandmarkBuilder` (`add`, `wall`, `spot`, `hash`). A road spine leaves the start yard south and one branch reaches each landmark.
- Districts: `districtSites(seed)` puts one site per cell of a 4 x 3 grid on a non-start chunk, a seeded shuffle gives every biome a site, and `biomeAt(seed, cx, cy)` is the nearest site. Start chunks are old town. Generic decor uses the biome's decor mix over `BASE_DECOR`; biome props roll in list order, roadside props stand on road slots, and at most `DISTRICTS.propCap` (14) props fit a chunk. Generic fences and bushes became props at the same spot and hash.
- `nearStaticColliders`, `nearProps` and `nearColliders` return data from the 3 x 3 chunks around a point. `ACTIVE` loads interactables within 1100 and drops idle far ones beyond 1500. `SPAWN_RING` places spawns just outside the view around `viewCentre(player)` with a 1500 leash.

- Water: pure `LandmarkDef.water` / `BiomeDef.water` shapes plus the fully shallow basin at (1040, 420), radii 76 x 46. `world-gen.ts` builds a bounded four-seed spatial index without calling `chunkContent`; road intersections add explicit crossing polygons, and `prepareWater` clips deep cores into convex solids minus decks. `waterRegionsNear` serves physics and Canvas, including negative coordinates. Generated props/building contacts avoid wet shores; start/road/court/lantern approaches remain clear.
- `game/water.ts`: `waterAt` reports dry/shallow/deep/bridge; shallow movement multiplies player/enemy speed by 0.68. `resolveWaterMove` sweeps actor circles with bounded tangent sliding, so dashes cannot tunnel through a core; `avoidDeepWater` handles spawn/recovery projection. Even scenery-ignoring normal enemy movement is water-constrained. Physics and `water-art.ts` use the same straight polygon edges, not independent art approximations.

### Simulation (`src/game/`)

- `createSim({ cat, seed, world, sessionSeconds })` builds a `SimState` with a single `player` whose `id` is the chosen cat, the starting weapon in `build.weapons`, and no companion slot. Weapon `init` hooks set their initial fields.
- `step` order: timers and the `tick` event, the player (skill through `CharacterDef.onSkill`, "move" weapons), `syncChunks`, `discoverLandmarks`, the page line, "aura" then "auto" weapons in registration order, shots, enemies (behaviours in order), leash, each enemy def's `stepWorld`, chests, pickups, interactables, treats, `stepFire`, then (only while still playing) `stepLandmarkActions`, schedule, phases, treats and horde spawning. The session is 600 s (`STATS.sessionSeconds`), with phases at `PHASE_AT` [0.15, 0.45, 0.8].
- `src/game/stats.ts` folds `playerStats(state)` in a fixed order: the chosen cat's base, every cat's `kitStats`, passives' `modify`, weapons' `stats` in registration order.
- **Horde (`src/defs/horde.ts`).** `HORDE.capByMinute` and `spawnPerSecondByMinute` ramp per tenth of the session and `HORDE.hardCap` (100) bounds everything alive, including splits, summons, waves and elites. `KIND_CAP` limits smudges (8) and crumples (14). `WAVES` are side, ring or line groups. `makeRoom()` rubs out off-screen commons first, farthest first, so elites and the Boss always fit; elites and the Boss are never removed.
- **Elites.** `ELITE` spawns a crowned common every 60 s from 60 s to 500 s (9x hp), skipped while the Boss lives. Each drops a chest.
- **Boss.** At `BOSS.spawnAt` 0.9 (540 s) the Eraser (420 hp) enters just outside the view. Beyond `huntRange` 360 it hunts at `huntSpeed` 92 and ignores scenery colliders. Sweep, summon and charge attacks are telegraphed (`enemies/eraser-boss/attacks.ts`). It drops reward shards and a big chest. User-confirmed rule (2026-11-17): defeating the Boss is optional. The cat may outrun it and still win by surviving until dawn; do not gate victory on a Boss kill.
- **Build.** `BUILD` has 3 weapon and 4 passive slots. Level-up cards offer 3 eligible weapons / passives of the chosen cat's pool, never evolutions, topped up with `snack`. `openChest` evolves when `readyEvolution(state)` holds (max base weapon + owned paired passive), otherwise raises owned items (`CHEST.levels` 1, `bigLevels` 3) or gives `snack`; the result is kept in `state.chestReveal`. User-confirmed rule (2026-11-17): if passive slots fill before the partner is acquired, the corresponding evolution is unavailable for that run. Do not reserve a slot or automatically grant the partner. This decision records the existing build consequence, not a request to add hints or a fallback.
- **Paper props (`src/game/props.ts`).** `elementHit` applies an element to every prop whose footprint overlaps a circle; `reactionFor(material, element)` picks the row; `damageProp` lowers durability (intact, damaged below `damagedBelow`, scraps at 0; burnt scraps are ash) and rolls seeded drops from the prop id hash (`drops.burst` spills a ring of shards). `SimState.props` is one compact map of touched props for the whole run. Standing props add colliders through `safePosition` using `propBlocks`; scraps and temporarily folded props open the path. Fold collision stays disabled until the lifecycle safely unfolds, even if the deadline passed. Weapon shots carry `elements[0]` through `shotTag`; claws, orbit stars and star-fall apply cut; lit pumpkins call `ignite(FIRE.pumpkinRadius)`.
- **Fire and actors.** `SimState.fire` holds 24-unit cells (2.4 s life, max 40) and bounded ash (500). Every 0.2 s, four-neighbor spread rolls use `hash2` at 0.35 x flammability; only standing dry fuel can ignite. Card/cloth flammability is 0.45/0.65. Each burning prop loses 0.5 durability once per tick, not per footprint cell. The user explicitly superseded the old harmless-to-cat rule: radius contact with the burning square refreshes 3 s carried burn; cats take 1 HP/1 s through normal `hurtPlayer` defenses/rescue/defeat, enemies 0.4/0.2 s through `hurtEnemy`. Arrival/dead enemies and decoys do not receive actor ticks; death-hook newborns are excluded from the current actor pass.
- **Water-first status.** `stepFire` removes wet cells, runs prop lifecycle, then `stepPaperStatus`, then fixed fire ticks. `PaperStatus` on player/enemies holds burn time, burn clock and wet time; it updates even with no live fire cells. Radius contact with exposed water extinguishes before a due burn hit/new ignition, resets the clock and grants 1.25 s wet protection. Decks are subtracted from wet shores, not treated as whole-actor exemptions: an actor reaching water beside a bridge still gets wet. Carried fire can ignite fuel at radius + 4 only on the fixed fire tick and never when wet.
- **Treatments and sources.** `PAPER_ELEMENTS` gives ink 9 s, fold 5 s, vat splash radius 76 x placement scale and wax heat scale 0.8. Ink prevents ignition/fuel consumption without changing HP/drop history, expires or washes off at a wet prop position. Fold only treats standing solid props, temporarily disabling collision without damage/loot. Deadlines refresh, not stack. Nicole applies fold at her field radius; each successful crane volley explicitly emits one radius-84/power-1 launch pulse while shots remain wind (`elements[0]`). Smudge applies ink once on landing; cut/wind vats splash without recursive self-ink. Wax heat uses burnt damage without reward or an invented ignition.
- **Safe lifecycle.** `stepPropLifecycle` resolves touched prop ids offscreen. Five flora opt into torn/burnt regrowth delays: grass 18/30 s, reeds 22/34, flowers 24/36, bush 28/42, mushroom 32/46. Unfold waits for collider occupancy plus 8-unit clearance; regrow also waits for nearby fire, retrying after 0.5 s. Restoration uses material-scaled max HP, clears old treatments/burn marks and only its own ash footprint. Torn drops roll once in a prop's lifetime; burning also claims the roll without loot; regrowth/tending never resets it. Handcrafted props remain scraps.
- **Landmark activities.** `LandmarkDef.activity` and shared `landmarkActivityPoint` drive `game/landmark-actions.ts`; state is per placed id (`progress`, `cooldown`, `activations`, `wind`, `turn`). Partial charge persists away, cooldowns advance offscreen, paused/upgrading/ended simulation does not advance them. Tea: 2.5 s proximity, radius 44, cooldown 32, heal 1. Observatory: 3 s proximity, radius 44, cooldown 48, radius-240 stun 3 s and shard value 4, not map reveal. Greenhouse: fold charge 2, radius 48, cooldown 45, treat plus schedule up to 10 renewable scraps within 320 through normal lifecycle; no direct HP/loot reset. Windmill: wind charge 3, radius 100, cooldown 24, radius-210 pulse (1.5 damage, 1.6 s stun, shard value 2). Element hits add at most 2 charge; cooldown locks before reward hooks. Wind refreshes a 6 s boost even while cooling; sim integrates turn at 0.25 idle / 2.6 boosted rad/s. `applyElement` dispatches props plus eligible activities.
- Full row matrix, source files and safety contracts: [paper-ecology.md](../../skills/midnight-meow-dev/references/paper-ecology.md). These intentional gameplay/world changes supersede original refactor-only snapshot equality, not deterministic simulation.
- **Interactions (`interactions.ts`).** Pumpkins and moon-lanterns come from the start yard spots (matching `scene.ts` props) and from landmark `spot` calls; `state.treats` holds fish treats placed near the cat with the sim RNG; a moon-lantern only announces it is full when it is near the view.
- **Feel.** `state.streak`, `impacts` (kinds in the `EffectKind` union, lifetimes in `EFFECT_LIFE` and `ENEMY_FX_LIFE`, capped by `FX_CAP`) and `notices` drive feedback. There is no spatial hash or object pool.
- RNG state is stored in `SimState.rngState`, so `snapshot` comparisons prove determinism. `main.ts` uses a fresh seed per run unless `?seed=N` pins it.

### Rendering (`src/render/`)

- **Art layer.** `art-registry.ts` defines `CatArt`, `EnemyArt`, `WeaponArt`, `PassiveArt`, `PropArt`, `LandmarkArt` (ground, reach, minimap ink, `DecorPiece`s), `BiomeArt` (swatch, patch) and their registries; helpers `catArt`, `activeWeaponArt`, `upgradeIcon`, `effectPainter`, `shotArt`, `decorPiece`, `landmarkReach`. `art-index.ts` registers every art file in def order. Shared painters (`craft-enemies.ts`, `combat-fx.ts`, `craft-juice.ts`, `cue-fx.ts`, `upgrade-icons.ts`) dispatch through the registries and do not switch on kinds.
- **Paper kit.** `paper-kit.ts` (`paperCut`, `paperStack`, `foldLine`, `stitchAlong`, `charEdge`, `tornEdge`, `warmGlow`) builds on `paper-material.ts`. `prop-kit.ts` `phasedPaint` derives damaged and scraps looks from one intact painter. `variants.ts` `variant(seed, base)` gives seeded palette, size, tilt, wear and mirror from the render-only `visHash`.
- `camera.ts` follows the cat with a 60 x 40 deadzone and 7/s smoothing, clamped to the world.
- `craft-world.ts` caches the ground of each chunk on 2x offscreen canvases (at most 14, one prefetch build per frame), with roads, hedge, landmark ground and district patches (150-unit render grid) baked in. Tall decor, landmark pieces and props are y-sorted cached sprites culled by bounds. Pop-up pieces fold toward the cat (`POPUP` in `timeline.ts`, folds kept in a render-only map, snapped under reduced motion). `landmarkPreview(kind)` serves the gallery. `navTargets` feeds edge arrows for landmarks, the nearest chest and the Boss. Chunk builds are synchronous.
- `craft-props.ts` draws prop phases/variants, alpha-masked ink and burn tints, folded cuts and regrowth anticipation that follows deferred sim restoration. Fire ground marks real square cells; only positive live cells produce flames. `paper-status-art.ts` adds read-only flame/char or damp drop/ripple overlays after actual player/enemy art, never decoys, plus steam, ink-wash, regrow and reward cues.
- `water-art.ts` draws shared shore/core vertices with shallow/deep contrast and dry decks after roads; no separate decorative water silhouette. Activity progress marks use shared court anchors and sim seconds/cooldowns. `DecorPiece.live` draws windmill sails once over a sail-free cached tower, with three cached rotor variants, continuous transforms and the same depth/pop-up placement; no time/angle cache keys. Tall building occlusion uses registered bounds.
- `craft-scene.ts` draws the sky, hills, ground tiles and dawn wash, reusing layout coordinates from the legacy `scene.ts` and pixel helpers (code dependency only). `craft-cat.ts` uses `paper-face.ts`'s cached color contours/silhouette derived from untouched official rectangle data, preserving visible overlap, small features, anchors and narrow edge; portraits share this source. `cat-detail.ts` retains finite articulated clothing/accessory parts. Enemy/combat art now uses finite cached faceted sheets, wings, sleeve parts, cranes, stars, flecks and open rings, not per-frame texture rebuilds.
- `timeline.ts` (pure) defines cue beats, slow motion, zoom, tremble, the card deal stagger and the pop-up fold. `presentationSteps` scales real time before `tickClock`, so the sim only sees `FIXED_DT` steps. `cue-fx.ts` draws the cues.
- `world.ts` composes layers with depth sorting and applies shake, tremble and zoom; `gallery.ts` paints the `?gallery=1` cards.
- Rendering reads `SimState` and world data only. It must not touch the RNG or mutate state.

### UI (`src/ui/`, `index.html`, `styles.css`)

- Screens: `title`, `play`, `pause`, `upgrade`, `result`, switched by `main.ts` via `document.body.dataset.screen`, plus `gallery` for `?gallery=1`.
- The look is a night-watch journal. `hud.ts` (badge, moon arc, lantern hearts, minimap, wick skill, XP seam, build tags, chest slip, Boss eraser bar) is painted through `src/render/journal-ui.ts`; `journal-geometry.ts` holds the pure geometry. Cat colours and status lines come from `CatArt`.
- `character-panel.ts` builds one ticket per registered cat (`buildCatTickets`) and reads numbers and copy params from the defs. `upgrade-cards.ts` deals lattice-window cards; `journal.ts` builds the result page (now 14 rows, including props torn and cells burnt); `ink.ts` reveals text; `touch.ts` adds the joystick and skill button.
- `gallery-layout.ts` (pure) builds sections (cats, enemies, props, landmarks, biomes, weapons, passives) and a non-overlapping grid from the registries. Five base prop previews do not automatically exercise every runtime treatment/status.
- `environment-copy.ts` gives localized burning status/help first priority. Wet status remains visible alongside nearby court action/cooldown hints; without a nearby court, wet help replaces the routine early-run hint. `hud.ts` displays these statuses; keys/notices/help/activity copy exist in zh and en.
- UI motion ideas come from Snapblocks' public descriptions and from video-shotcraft's beat structure, rebuilt in CSS / Canvas; no code is copied. Motion is reduced under `prefers-reduced-motion`.
- Preferences `{ locale, cat, muted }` persist in `localStorage` key `midnight-meow-prefs`; any registered cat id is accepted.

### Audio (`src/audio/sfx.ts`)

- Oscillators and generated noise buffers only; no audio files. The `AudioContext` is created on the first pointerdown / keydown.
- `main.ts` keeps a `cueState` and diffs sim counters each frame (shots, hits, defeats, level-ups, boss events, interactions, props torn, burning cells) to trigger sound and timeline cues, so the sim stays free of audio. New cues: `tear` and a throttled `crackle` while anything burns.

### Localization (`src/content/`)

- `keys.ts` lists every message key; `en.ts` and `zh.ts` implement them; `t(locale, key, values)` formats them; `missingKeys` must be empty for both packs.
- Each def family has its keys (`upgrade.<id>.*`, `enemy.<id>.name`, `prop.<id>.name`, `landmark.<id>`, `notice.found-<id>`, `biome.<id>.name`, cat copy under its `i18n` prefix).
- Current default locale is `en`; both packs are complete and saved locale choices override the default.

### Paper ruleset, wash-out and paper verbs (2026-11-18)

- **Ruleset.** `src/render/paper-rules.ts` holds one moon light (top-right), one hard down-right shadow, 1 to 3 flat layers and `PAPER_VALUE`; flat helpers live in `paper-kit.ts`. `paper-value.ts` grades baked ground/decor and adds a lit rim to enemy parts and the live cat. Gallery check views `?gallery=1&check=value|gloss`.
- **Wash-out.** `src/defs/wash.ts` (numbers), `src/game/wash.ts` (sparse 32-unit grid in `SimState.wash`, sources, slow/fire/tear effects, sketch wakes, restoration, `colourKept`), `SimContext.wash` / `paint`. Render: `wash-art.ts` masks per chunk (null frame when empty), pencil chunk tiles in the shared 14-tile budget, `pencil.ts`, `sprite-sketch.ts`. Full contract in `.kiro/skills/midnight-meow-dev/references/paper-ecology.md`.
- **Paper verbs.** `weapons/paper-cut.ts` (Zero) and `weapons/page-fold.ts` (Nicole) with `defs/weapons/paper-geometry.ts`; `SimState.cut`, `fold`, `walls`; `ctx.elementHit(..., within)` polygon filter. Cat wear in `cat-detail.ts`; snip/fold cues from sim counters.

## Testing

Latest verification: **`npm run build && npm test` passed 295 tests**. `npm test` builds `dist/` plus isolated `site/` and runs `node:test` suites. New in the wash-out round: `paper-rules`, `wash`, `paper-verbs`, `paper-value`.

- `registry.test.mjs`: pools, exclusives, evolution pairs, spawn tables, i18n keys for every def, duplicate / unknown ids, event bus order, engine isolation, no cat literals in game / render / UI / main, art registries match defs, icons, cached sprites, landmark and biome art, layouts and biome prop mixes.
- `reactions.test.mjs`: tearing and scraps colliders, fire spread, cap and enemy damage, non-flammable materials, determinism with props and fire, persistence across chunk reloads, migrated props, reaction table integrity, pop-up fold, scarecrow burst, straw fire.
- `environment-integration.test.mjs`: main-step slowing/extinguishing, real activity dispatch/rotor integration, localized hazard priority and no post-defeat pickup/upgrade.
- `fire-water.test.mjs`: radius ignition, normal defense/death handling, carried burn and wet priority/decks, bounded spread, safe regrowth/unfolding and lifetime loot claims.
- `landmark-actions.test.mjs`: court access, proximity/element triggers, offscreen progress/cooldowns, finite rewards, safe greenhouse scheduling and deterministic RNG-free state.
- `paper-elements.test.mjs`: row uniqueness, treatment deadlines/material-scaled HP, smudge/vat ink, wax consumption, Nicole/crane fold and preserved weapon behavior.
- `paper-visuals.test.mjs`: read-only actor/prop cues, live-cell marks, finite enemy/combat caches, court anchors and registered-bounds occlusion; static command tests, not motion/FPS.
- `water.test.mjs`: local pure regions, shared polygon vertices, radius sweeps/spawn recovery, shallow/deep/decks, road crossings, teaching basin and placement clearance.
